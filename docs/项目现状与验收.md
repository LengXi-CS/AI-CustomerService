## 消息到回复的链路

1. 接收微信回调，配置群消息进入本地归档及当天群上下文；归档不等于建立需求。个人名片42、企业微信名片66仅作为名片记录，不进入需求拆分、安抚或人工接管。私聊名片忽略，当前聊天归档只覆盖配置群。
2. 可处理的客户文字先保存原消息和待处理身份，再调用模型拆分需求。同群同客户按到达顺序落库；图片先持久登记，后续文字原子绑定尚未消费的同客户图片。
3. 开启事项关联的群，在后台结合原话、引用和当天上下文识别补充关系。不同客户、独立订单及主题隔离，关联失败保留待判并重试。同一事项统一计时、持久化安抚回执。
4. 人工回复能明确定位时接管对应事项，否则进入待判。人工接管跨午夜和重启保留，已安抚事项的后续催办也继承接管；明确引用并@机器人交回时重新核验控制状态。较早入站消息仍在拆分、人工待判或需求待关联时，相关自动任务继续等待。
5. 等待到期后领取任务，恢复原始需求、补充及绑定媒体。模型生成简短安抚；负责人通知配置决定是否允许“反馈核实”等动作表述。发送前重查等待时间、任务版本及人工状态，避免生成过程中状态变化导致抢答。
6. 引用配置及原消息元数据完整时发送原生引用，否则使用事项摘要文本。发送结果不明时保留回执状态，不能当作未发送而立即重发。撤回消息由持久标记拦截，重复回调或重启也不能重新建有效任务。

当天消息可在本地完整查看，送入模型的文本仍有60000字符预算，优先保留当前需求、引用及人工回复；这不等于把全天所有原文无条件塞入每次模型调用。详见[人工接管说明](当天上下文与人工接管.md)及[安抚话术生成](安抚话术生成.md)。

## 按群等待与生效方式

入口：WebUI“回复策略 → 各群客户发言后等待时间”。每群可设置0–86400整数秒；勾选“跟随默认”则删除TOML覆盖项，继承服务当前运行的全局默认。0是明确的不额外等待，仍有模型处理及轮询耗时。同事项有效补充从最后一条重新计时，名片不重置等待。

| 修改内容 | 生效方式 |
|---|---|
| 群独立等待、群开关、引用及关联策略、安抚模式和固定文案 | 保存后，下次调度或业务读取群策略时热加载 |
| 全局默认等待、轮询间隔、模型及连接等 `.env` 参数 | 重启后生效；页面以“当前运行”值区分待重启配置 |
| Python 代码及提示词 | 重启Windows服务加载 |
| 前端源码 | 重新构建管理页静态资源并刷新浏览器；新增后端接口同时需要重启 |

待发送任务按新群等待值重新判断；已经开始发送的消息不能撤回。保存等待时间复用群配置版本校验、备份和修改记录；旧备份没有覆盖项时恢复为跟随默认。本轮开发未替用户修改各群等待值。详见[WebUI说明](群管理WebUI.md)和[配置项速查](配置项速查.md)。

## 运行环境与重启核验

本机根目录为 `D:\瀚思AI客服`，后端由NSSM托管为 `FastGptAssistant`，端口5330，采用单个Uvicorn进程。持久状态配合进程内顺序、活跃回调及配置锁工作，当前没有多worker部署保证。

当前回调转发依赖本机Docker引擎及frpc容器，经远端frps转至本地5330；公网地址以实际隧道配置和GeWe注册值为准。旧文档的cpolar域名及带宽数据属于历史部署。WebUI分别展示Docker/frpc和AidNet主程序/连接进程；进程运行不能证明公网回调、微信节点或负责人私聊已可达。

在管理员PowerShell中，项目根目录执行既有脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\瀚思AI客服\scripts\restart_app.ps1"
```

脚本先只读列出未终态任务，再重启服务并检查 `/health`；这些任务可能在首次轮询继续处理。核验时同时检查运行状态页的服务启动时间晚于待部署源码修改时间、调度器正常、待重启配置已一致，并查看 `logs/5330.err.log` 的新启动记录。健康检查通过只证明相应本地检查通过，不能证明某条业务场景已经验收。公网回调仍在GeWe中检测。

截至最近一次核验，名片补修已通过代码测试，尚无补修后重启加载的确认。本次文档更新没有重启服务、修改线上任务或发送微信。详细部署步骤见[Windows部署指南](../快速部署指南-Windows服务器.md)。
